# P2 对数输入整形 + 多轨迹权重平均 · 实验记录

日期：2026-11-23　数据集：`cpu-b-rul-20261110-v1`（训练 7032 行 / 9 轴承，验证 1679 行 / 3 轴承）
起点：官方 `checkpoint.npz`（15 epoch / 825 步）　超参：lr 3e-2、bs 96、目标幂 p、多轨迹见正文

> 本记录是 P1（`P1_末端修正_实验记录.md`）的续篇。P1 把 RMSE 从 681.16 压到 464.22；
> 本记录把 464.22 压到 **313.79**，并记录四次失败的尝试——失败的路径同样写进来，
> 因为答辩被追问"你试过什么"时，能说出"试过且为什么不行"比只报成功更有说服力。

## 一、为什么 464.22 不算成果

先做了一次冷静的复测：把 P1 的最优配置（abs8、p=0.5、bs96、45 epoch）在 4 个 batch_size 上各跑一遍。

| 配置 | RMSE |
|---|---|
| bs 96 | 464.22 |
| bs 128 | 516.79 |
| bs 192 | 550.24 |
| bs 256 | 562.76 |
| **均值** | **516.10** |

464.22 是好运气，不是水平。同一份代码换一个 batch_size 就差 86 分。而训练与验证的误差比是 2.06～4.02（训练 150～225，验证 464～590）——**这是明显的过拟合，不是容量不足**。

更要命的是预测形态。把验证集按轴承拆开看：

| 轴承 | 样本 | 真实 RUL 范围 | 预测范围 | 偏差均值 |
|---|---|---|---|---|
| Bearing3_4 | 1515（90%） | 0 → 1514 | 143 → 411 | **−269** |
| Bearing1_4 | 122 | 121 → 0 | 0 → 1210 | +200 |
| Bearing2_4 | 42 | 41 → 0 | 0 → 777 | +253 |

3_4 的真实寿命从 1514 线性掉到 0，模型给出的却是一条几乎水平的线（411→143）。**它没有跟随退化过程，只是在输出条件均值。** 这也解释了为什么 464.22 只比"常数=训练集中位数"的 470.86 好 1.4%——模型实际上退化成了常数预测器。

再补一个诊断：留一轴承交叉验证（9 根训练轴承，每次留一根，用其余 8 根训练）。

| 留出轴承 | RMSE |
|---|---|
| Bearing1_1 | 188.17 |
| Bearing1_2 | 109.41 |
| Bearing1_3 | 693.76 |
| Bearing2_1 | 206.42 |
| Bearing2_2 | 622.41 |
| Bearing2_3 | 223.23 |
| Bearing3_1 | 1265.72 |
| Bearing3_2 | 1371.34 |
| Bearing3_3 | 1049.98 |
| **合并 OOF** | **1153.78** |

常数预测在训练集上是 809.24，比模型的 1153.78 还好。**模型学到的主要是"这根轴承属于哪个工况、寿命大概多长"，不是"退化到什么阶段"。** 验证集上之所以还能到 464，是因为 3_4 在训练集里有 3_1/3_2/3_3 三个同工况兄弟，工况记忆碰巧生效。

这个发现决定了后面的方向：**必须在"同工况泛化"这个前提下提升，而不能靠加深对工况的记忆。**

## 二、四条走不通的路（都实测过）

### 2.1 正则化

| 手段 | RMSE 均值（4 个 bs） | 对比基线 516.10 |
|---|---|---|
| 输入高斯噪声 σ=0.05 | 573.69 | +11% |
| σ=0.10 | 613.27 | +19% |
| 权重衰减 1e-4 | 545.32 | +6% |
| 1e-3 | 609.83 | +18% |
| Dropout 0.1 | 训练中断（实现缺陷），未完成 |
| 余弦退火 lr | 597.19 | +16% |
| 步进衰减（每 15 轮 ×0.4） | 603.67 | +17% |
| 权重平均（EMA 0.9） | 546.87 | +6% |
| 只平均最后 10 轮的权重 | 579.93 | +12% |

**过拟合严重，但所有正则化都让验证误差变大。** 这个反常现象的解释是：模型的误差不是"方差过大"而是"系统性偏差"——它把工况记错方向了，加正则只会让它更保守地输出均值，而均值本身就比 464 差。

### 2.2 样本重加权

训练集极度偏斜：Bearing3_1（2538 行）+ Bearing3_2（2496 行）占 71.6%，而验证集 3_4 只到 1514 分钟。直觉上应该按轴承等权或按 RUL 分箱均衡。

| 加权方式 | RMSE 均值 |
|---|---|
| 无 | 516.10 |
| 轴承等权 | 635.15 |
| 轴承按 1/√n | 635.73 |
| 按 1/(1+y/500) 降权高 RUL | 631.33 |
| RUL 分 5 箱均衡 | 526.27 |
| RUL 分 10 箱均衡 | 515.53 |

全部持平或变差。原因：长寿命轴承虽然样本多，但它们是唯一提供"高 RUL 段"信息的来源；把它降权等于删掉大半有效监督。

### 2.3 数据增强（轴承内相邻快照插值）

按快照序号排序，在相邻样本之间按随机比例插值特征与目标。

| 增强倍数 | RMSE 均值 |
|---|---|
| 无 | 510.42 |
| ×2 | 554.81 |
| ×3 | 602.08 |
| ×5 | 573.93 |
| ×9 | 642.19 |

末端指标确实改善（tail100 从 226.5 降到 178.5），但总体变差。插值生成的是"同一条轨迹上的中间点"，不增加跨轴承多样性——**过拟合的本质是轴承数太少（9 条轨迹），不是同一条轨迹上的点太少**。

### 2.4 输入分布的尺度矫正

猜测是"验证集特征落在训练分布之外导致 tanh 饱和"，于是试了三种尺度矫正：

| 手段 | RMSE 均值 |
|---|---|
| 秩变换（训练集 ECDF → 标准正态）+ abs8 | 609.11 |
| 秩变换，不做 abs8 | 771.59 |
| 原始 + abs8（对照） | 516.10 |

同时检查了越界率：验证集特征落在训练集[min, max]之外的比例只有 0.0%～0.1%。**不是分布外推问题**，这个假设被推翻。

## 三、转折：14 列对数绝对量

P1 有一个被忽略的线索：训练集内与 RUL 相关性最强的特征，全部是"绝对量"——`band3_energy_6k_12k`（6–12 kHz 频带能量）的轴承内 Spearman 达 −0.84，`rms`、`mean_abs`、`spectral_rms` 在 −0.76 左右。而形态类特征（峭度、峰值因子、裕度因子）只有 0.13～0.23。

问题在于这些量的**跨轴承尺度差异极大**：

| 轴承 | rms(水平) 中位数 | band1 能量中位数 |
|---|---|---|
| Bearing2_1 | 0.364 | 0.041 |
| Bearing1_2 | 2.541 | 2.229 |
| Bearing3_2 | 1.045 | 0.199 |

同一物理量差 7 倍。P1 的 abs8 用"通道内 8 个绝对量互为参照"来消掉这个尺度差，但它同时把"能量水平"这个最强信号归一掉了。

于是加一层：**在两通道各追加 7 列对数绝对量**（rms、peak、mean_abs、spectral_rms、band1、band2、band3，共 14 列）。取对数不是为了"让分布更正态"，而是为了**不让缓慢退化段的微小趋势被线性尺度淹没**。

证据来自 3_4 那根轴承的分段统计（10 等分，看均值怎么走）：

| 特征 | 前 9 段的均值走势 | 最后一段 |
|---|---|---|
| v_band3_energy_6k_12k | 0.022 → 0.021 → 0.018 → 0.018 → 0.018 → 0.020 → 0.035 → 0.032 → 0.043 | 0.247 |
| v_rms | 0.634 → 0.633 → 0.622 → 0.610 → 0.605 → 0.609 → 0.640 → 0.630 → 0.659 | 2.231 |

前 9 段（占寿命 90%）能量只从 0.022 涨到 0.043，**翻倍但在原始尺度上几乎看不出来**；最后一段突然爆到 0.247。取对数后，0.022→0.043 对应 −3.82→−3.15，是 0.67 个单位的位移，在标准化后完全可见。

单加这 14 列（单轨迹、bs96、45 epoch、p=0.5）就把 464.22 打到 **400.47**，降幅 13.7%。但换 bs 到 128 又回到 595.16——**只加特征不解决问题，方差依旧。**

## 四、第二根支柱：多轨迹权重平均

单条轨迹对 batch_size 极度敏感（439～711），说明它拟合到了训练集里偶然的结构。既然不同 batch_size 看到的是**同一个信号的不同的噪声实现**，那就跑多条轨迹、把权重取算术平均。

先验证一个反直觉的事实（这一步很关键）：**权重平均本身不是万能的**。

| 输入维度 | 单轨迹（bs96） | 6 条轨迹权重平均 |
|---|---|---|
| 34 维（原始 + abs8） | 414.97 | **515.74（更差！）** |
| 48 维（+14 列对数绝对量） | 434.68 | **313.79（大幅更好）** |

（同口径：p=0.45、105 epoch、lr 3e-2、从官方起点续训、轨迹集 96/112/128/144/192/256）

**34 维下做平均反而变差 26%。** 因为信号太弱时，6 条轨迹学到的是同一个错误（"按工况猜寿命"），平均只是把同一个偏差求得更精确。而 48 维下 log 列提供了足够强的退化信号，各轨迹的正确部分一致、噪声部分独立，平均才有意义。

所以三个条件缺一不可：**对数特征（供信号）+ 多轨迹（降噪）+ 目标幂 0.45（压末端）**。少任何一个，结果都回到 400～520。

## 六、最终结果

| 指标 | 官方基线 | 常数（训练中位数） | P1 最优 | **P2 最优** | 相对官方 |
|---|---|---|---|---|---|
| RMSE | 681.16 | 470.86 | 464.22 | **313.79** | **−53.9%** |
| MAE | 563.11 | 410.94 | 350.97 | **242.29** | **−57.0%** |
| 末端 RMSE（<100 分钟，n=242） | — | — | 236.74 | 276.66 | — |
| 末端 RMSE（<50 分钟，n=142） | — | — | 235.3 | 251.83 | — |

分轴承：

| 轴承 | 样本 | 真实均值 | P1 预测均值 | P2 预测均值 | P1 RMSE | P2 RMSE |
|---|---|---|---|---|---|---|
| Bearing1_4 | 122 | 60.5 | 260.7 | 279.2 | 274.8 | 254.8 |
| Bearing2_4 | 42 | 20.5 | 273.4 | 241.7 | 345.2 | 304.1 |
| Bearing3_4 | 1515 | 757.0 | 487.8 | 579.7 | 479.0 | 318.3 |

3_4（占 90% 样本）的 RMSE 从 479.0 降到 318.3，预测均值从 487.8 抬到 579.7（真实 757.0）——**方向对了，幅度也接近了一倍**。三根轴承的 RMSE 全部下降。

**必须承认的退让**：末端指标从 236.74 变成 276.66（+16.9%）。拆开看，退化全部来自 3_4：

| 轴承（RUL<100 的子集） | 样本 | P1 RMSE | P2 RMSE | P1 预测均值 | P2 预测均值 |
|---|---|---|---|---|---|
| Bearing1_4 | 100 | 248.83 | 269.88 | 214.8 | 281.3 |
| Bearing2_4 | 42 | 345.15 | 304.10 | 273.4 | 241.7 |
| Bearing3_4 | 100 | **153.88** | **271.22** | 136.6 | 227.2 |

P1 在 3_4 的末端只有 153.88，压得非常准；P2 把整体尺度抬高之后，3_4 的末端预测从 136.6 抬到 227.2，末端误差跟着涨。这是"整体跟随"与"末端压低"之间的跷跷板：P1 的 p=0.5 把曲线整体往下压，末端恰好压对但中段全错；P2 让曲线跟随真实趋势，末端就略微抬高。

一句话：**总体 −32%（相对 P1）、−54%（相对官方），代价是 3_4 的末端 +117 分。** 这个交换在总 RMSE 上是明确的净收益，但末端是平台单列评分项（"最差阶段与恢复速度"），所以这一条必须主动说，不能等评委问。门控里的末端权衡条款（`TAIL_TRADE_GAIN` / `TAIL_TRADE_RMSE`）本来就是为这种情形准备的：如果平台更看重末端，把 `ZXJ_TARGET_POWER` 调回 0.5 即可回到 P1 的形态，开关在环境变量里，不需要改代码。

## 七、复现

```bash
cd pkg_b
export ZXJ_INPUT_MODE=abs8log ZXJ_TARGET_POWER=0.45
export ENSEMBLE_BATCH=96,112,128,144,192,256

python -m baselines.train --profile B \
  --train public/train.jsonl --validation public/validation.jsonl \
  --output /tmp/p2 --from-baseline checkpoint.npz \
  --epochs 105 --learning-rate 0.03 --batch-size 96 \
  --ensemble 96,112,128,144,192,256
# 期望 validation_after.rmse = 313.7901，mae = 242.2905
```

单次训练耗时：CPU 2 线程下约 21～27 秒（6 条轨迹合计）。

容器内闭环（不配大模型凭证，走策略表）：

```bash
docker run --rm zxj-harness:0.2
# 期望 summary.json: best_rmse = 313.79，accepted_rounds = [1]
```

## 八、局限

1. **验证集只有 3 根轴承**，其中 3_4 占 90% 样本。任何在验证集上的 5% 级改进都在噪声边界内，所以本文所有选型都要求"邻域内多个取值同时成立"，而不是取单点最优。
2. **留一轴承 OOF 仍然是 1153.78**（P1 口径）。P2 没有重新跑 LOBO，因为它改变了输入维度，需要重跑 9 折；这一步列为后续工作。**在真正的新工况上，本方案的优势会明显小于验证集上的数字**，这一点必须预先说明。
3. **多轨迹把单轮训练时间放大 6 倍**（从 3 秒到 21 秒）。在平台给的评测时长内完全够用，但如果平台把 EPOCH_BUDGET 压到 50 以内，只能退化为单轨迹，此时最好结果是 434.68，仍优于官方基线 36%。
4. **1_4/2_4 的末端高估没有解决**。它们在训练集里的同类样本（Bearing1_1 123 行、Bearing2_4 对应工况只有 491/533 行）太少，模型没有足够的短寿命样本来校准。
