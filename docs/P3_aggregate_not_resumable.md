# P3：集成平均点为什么不能继续训练

时间：2026-11-23 21:50
起因：闭环第 2、3 轮反复出现远超基线的结果（357.19 / 641.78 / 651.75），此前记为
"从已收敛点继续用 lr 0.03 偏大，门控挡住，未修"。
本文件给出实测定位：**不是学习率问题，是权重平均点本身不可续训**。

---

## 一、实验（全部从容器内采纳的那一版起训，同一份数据、同一配置）

起点：`runs_image_v02/round-01/checkpoint.npz`，验证集 RMSE **302.75**（容器口径）。
续训参数：`ZXJ_INPUT_MODE=abs8log`、`ZXJ_TARGET_POWER=0.45`、
`ENSEMBLE_BATCH=96,112,128,144,192,256`，lr 与轮数按下表变化。

| 轮数 | 学习率 | 合并后 RMSE | 相对 302.75 | 6 条轨迹各自的 RMSE |
|---|---|---|---|---|
| 90 | 0.03 | 649.65 | +114.6% | 568 / 539 / 602 / 646 / 619 / 656 |
| 20 | 0.01 | 505.91 | +67.1% | 527 / 516 / 495 / 508 / 492 / 493 |
| 15 | 0.015 | 517.92 | +71.1% | 509 / 498 / 531 / 514 / 514 / 523 |
| 3 | 0.001 | 361.78 | +19.5% | 374 / 369 / 366 / 362 / 353 / 348 |
| 3 | 0.0001 | 352.73 | +16.5% | **354 / 354 / 354 / 353 / 352 / 351** |

两点结论：

1. **学习率降到万分之一、只训 3 轮，仍然退步 16.5%**。所以"lr 太大"不成立。
2. 最后一行是决定性证据：6 条轨迹的 RMSE 从原来的 381~705（彼此差一倍）收敛到
   **352~354，彼此只差 3 分**。也就是说，从平均点出发的第一批梯度，把 6 条轨迹
   **拽回了同一个解**。

## 二、机理

权重平均的收益来自"6 个函数的平均"（方差抵消），而不是"这组权重落在某个好解上"。
平均点的梯度方向指向的是**某一条单轨迹的解**，不是 6 条轨迹的共同低误差区。

一旦从平均点继续训练，6 条轨迹立刻落到同一条轨迹上，集成结构消失，模型回到
"单轨迹水平"（350 上下）。这解释了为什么任何学习率都会掉到 350 一线：
掉到的不是"更差的解"，而是"单模型本来的解"。

这也与第一版能复现、而第二版不能续训的现象一致：第一版是单轨迹模型（34 维），
从它续训掉到 500 是过拟合；第二版是集成点，从它续训掉到 350 是去集成化。

## 三、修法（已实现）

要害不在调参，而在**不要把平均点当下一轮的起点**。

`baselines/train.py`：集成合并时写入 `meta["aggregate"] = "weight_average"`、
`meta["ensemble"] = [96,112,128,144,192,256]`。

`harness/executor.py`：每轮开始前检查父检查点，若为权重平均产物，**改从官方起点独立训练**
（`resume=spec.ckpt`），并在决策记录里写 `restarted_from_start: true` 与
`requested_parent_sha256`，保留"原本想从哪儿起"的证据。

`harness/observer.py` / `planner.py`：把 `best_is_aggregate` 作为事实喂给提案器；
命中时提案理由改为"当前最优为集成平均点，不可续训；从官方起点独立训练候选 #n"，
不再错误地声称"衰减学习率细化"。

这样每轮都是**从同一官方起点出发的一次独立实验**，与 `policy.json` 候选表里
prior_rmse 的测量口径一致（那批数本来就是在官方起点上单独跑出来的）。

## 四、影响面

- 硬件与权重不变：首轮仍是 105 epoch、lr 0.03、6 条轨迹、302.75，**主指标不变**。
- 第 2、3 轮从"必然劣化的续训"变成"两个可比的独立候选"（90ep → 325.5、60ep → 343.4），
  仍被门控回滚，但循环的语义正确了：**搜索配置，而不是在好模型上做破坏性续训**。
- 省掉的是解释成本：原来要在答辩里说"第 2/3 轮不知道为什么发散"，现在有 5 组实验和机理。

## 五、仍然成立的限制

1. 集成点不可续训意味着**这套方法没有"越训越好"的累积能力**，本质是"从固定起点多次
   独立尝试 + 选优"。这一点写进报告，不要包装成在线学习。
2. 若平台把 `ENSEMBLE_BATCH` 置空（单轨迹模式），`aggregate` 标记不会写入，
   续训退化为原来的行为，门控仍需把关。
3. 本结论在 48 维 + p=0.45 配置上验证；34 维单轨迹配置不存在这个问题（但那一版本身是过拟合）。
