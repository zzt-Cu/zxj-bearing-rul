[1] 任务定义
----------------------------------------------------------------
任务类型      ：regression（回归）
预测目标      ：剩余使用寿命 RUL
输出单位      ：minutes（分钟）
评价指标      ：RMSE（主）、MAE（辅），越低越好
特征维度      ：34（horizontal / vertical 两个通道 × 17 个特征）
输入形式      ：单条样本 = 34 维实数向量，来自振动信号特征提取结果

[2] 模型结构（赛题锁定，不可修改）
----------------------------------------------------------------
模型格式      ：contest.cpu-mlp.v1
结构          ：单隐层全连接 MLP，48 -> 24 -> 1（输入宽度为派生后宽度）
隐层宽度      ：hidden = 24（锁定）
激活函数      ：tanh
参数量        ：1,201
随机种子      ：seed = 42（锁定，不可更换）
设备          ：cpu
计算框架      ：numpy 1.26.4（镜像内版本，无 GPU、无深度学习框架依赖）

说明：hidden / seed / paths（34 维特征清单）/ task 四项由赛题校验，任何改动都会
      被 baselines/train.py 的 --resume 校验拒绝；本方案四项一字未改，实测通过。
      输入宽度 34 -> 48 不是改了特征集：外部仍只提供官方 34 维，额外 14 列由代码
      在训练与预测两侧从这 34 维现算得出，不依赖任何新输入。

[3] 输入整形（本方案新增，默认启用）
----------------------------------------------------------------
整形模式      ：input_mode = abs8log（即 abs8 + 14 列对数绝对量）
第一层        ：按训练集统计量整体标准化并裁剪到 [-10, 10]
第二层 abs8   ：对“绝对量特征”按单条样本自身做通道内标准化（每通道 8 个，共 16 维）
                band1_energy_0_2k / band2_energy_2k_6k / band3_energy_6k_12k /
                mean_abs / peak / peak_to_peak / rms / spectral_rms
                horizontal 维索引：[0, 1, 2, 8, 9, 10, 11, 16]
                vertical   维索引：[17, 18, 19, 25, 26, 27, 28, 33]
第三层 log14  ：追加 14 列自然对数绝对量（两通道 × 7），按训练集统计量标准化后
                裁到 [-10, 10]，列顺序固定为
                horizontal: rms / peak / mean_abs / spectral_rms / band1 / band2 / band3
                vertical  : rms / peak / mean_abs / spectral_rms / band1 / band2 / band3
                下限保护：log(max(x, 1e-12))
设计依据      ：abs8 消掉了跨轴承尺度差，但同时把“能量水平”这个最强信号归一掉了
                （band3_energy 的轴承内 Spearman 达 -0.84，形态类特征只有 0.13~0.23）。
                log14 把能量水平以相对形式补回；取对数是为了让前 90% 寿命段里
                0.022 -> 0.043 这种翻倍趋势在标准化后仍然可见。
消融开关      ：ZXJ_INPUT_MODE=none（关闭全部整形）/ abs8（只做通道内归一）

[4] 目标变换（本方案新增，默认启用）
----------------------------------------------------------------
变换形式      ：y' = y ^ p，p = 0.45
变换后标准化  ：(y' - target_mean) / target_scale
target_mean   ：19.48634176662611
target_scale  ：9.185445401063111
反变换        ：y = (z * target_scale + target_mean) ^ (1/p)
设计依据      ：p=1.0 时寿命末端严重高估；p=0.5（v2）末端压得最准但整体曲线被
                压低，中段全错；p=0.45 让曲线跟随真实退化趋势，总体最优。
                48 维 + 6 轨迹口径下，p∈{0.43,0.45}、epoch∈{90,105,120} 六种组合
                都落在 303~326；p=0.43/105ep 的 302.76 是孤立尖峰（p=0.44 为 395.69），
                故不采用，选 0.45/105ep 的 313.79 作为稳健点。
兼容性        ：旧检查点若无 target_power 字段按 1.0 处理；幂次与统计量一并写入
                检查点 meta，载入时与进程配置不符直接报错终止。
消融开关      ：ZXJ_TARGET_POWER=1.0（关闭）/ 0.5（回到 v2 形态）

[5] 训练超参数
----------------------------------------------------------------
初始学习率    ：learning_rate = 0.03
批大小        ：batch_size = 96（单轨迹基准；集成见下）
单轮 epoch    ：105
优化器        ：Adam（官方基线实现，未改动；beta1 0.9 / beta2 0.999 / eps 1e-8）
梯度裁剪      ：clip_norm = 5.0（官方实现，未改）
训练起点      ：checkpoint.npz（赛题提供的官方起点，未替换）
累计轮次参考  ：checkpoint meta 记 epochs = 120（起点 15 + 本轮 105）
累计步数参考  ：825 -> 6180

多轨迹集成（本方案新增）

开关          ：ENSEMBLE_BATCH = 96,112,128,144,192,256（6 条）
做法          ：同一续训起点、同一轮数与学习率，只改 batch_size，各训一条轨迹；
                训练结束后对 w1/w2/b1/b2 与 Adam 一阶、二阶矩取算术平均。
目标空间同步  ：合并后 target_power / target_mean / target_scale 必须取轨迹值，
                不能沿用起点值（否则预测落在错误空间，会“看起来可用”其实错）。
初始化细节    ：从 34 维起点扩展输入宽度时，新增 14 列用与常规初始化同分布的小
                随机数起步，不置零（置零会让这 14 列长期拿不到有效梯度）。
实测          ：6 条单轨迹分别 434.68 / 402.89 / 711.43 / 663.12 / 516.58 / 468.79
                （均值 532.9），合并后 313.79，比最好单条还好 22%。
反例          ：34 维（不加 log14）做同样 6 轨迹平均是 515.74，比单轨迹 414.97 更差。

[7] 输入输出契约
----------------------------------------------------------------
输入（单条预测请求，stdin，每行一条）：
  {"task": "regression",
   "inputs": {"features": {"horizontal": {17 个特征}, "vertical": {17 个特征}}}}
  说明：请求体只允许 task 与 inputs 两个键；task 可省略，省略时取检查点 meta 内值。
        特征顺序由检查点内 paths 固化，顺序不符会直接报错，不会静默给出错误结果。
        34 维之外的 14 列对数绝对量由代码内部生成，调用方不需要提供。
        解析器主动拒绝任何标签类字段（rul / remainingusefullife / normalizedrul /
        truerul / totalsnapshots 等），用于证明预测链路拿不到真实寿命。

输出（stdout，每行一条）：
  {"outputs": {"value": <float>}}     单位：分钟；预测为负时截断为 0

调用方式：
  echo '{"inputs":{"features":{...}}}' | \
    python -m baselines.predict --checkpoint runs/round-01/checkpoint.npz

决策日志（runs/decisions.jsonl，每轮一条）：
  round / ts / observation / proposal / result / execution / decision
  result   含 rmse、mae、tail_rmse、tail_mae、tail_n、worst_group、groups（分轴承）
  execution 含 checkpoint、checkpoint_sha256、parent_checkpoint_sha256、
           initial_steps、final_steps、training_seconds

[8] 检查点与产物
----------------------------------------------------------------
格式          ：npz（numpy 压缩归档），含 w1/b1/w2/b2、mean/scale、Adam 状态与 metadata
meta 关键字段 ：format / task / paths / hidden / seed / epochs / steps /
                learning_rate / batch_size / parameter_count / input_mode /
                input_width / derived / target_mean / target_scale / target_power
                （容器实测值：input_mode=abs8log, input_width=48, derived=logabs14,
                  parameter_count=1201, target_power=0.45, batch_size=96）
校验行为      ：load 时若 input_mode、target_power 或 input_width 与当前进程不一致，
                直接抛错终止，不静默产出错误预测。

[9] 复现命令
----------------------------------------------------------------
容器默认（无参数即运行完整闭环，内置上述全部配置）：
  python -m harness.loop

等价显式写法：
  python -m harness.loop --data /app/public --ckpt /app/checkpoint.npz --run-dir /app/runs

单轮复现（宿主机，验证 313.79）：
  export ZXJ_INPUT_MODE=abs8log ZXJ_TARGET_POWER=0.45
  export ENSEMBLE_BATCH=96,112,128,144,192,256
  python -m baselines.train --profile B --train public/train.jsonl \
    --validation public/validation.jsonl --output /tmp/p2 --from-baseline checkpoint.npz \
    --epochs 105 --learning-rate 0.03 --batch-size 96 \
    --ensemble 96,112,128,144,192,256
  # 期望 validation_after.rmse = 313.7901，mae = 242.2905

容器自检（10 项）：
  python selfcheck.py

大模型连通性探测：
  python pytrio_probe.py

[10] 已知限制
----------------------------------------------------------------
1. 末端指标退让：末端 RMSE（<100 分钟，n=242）从 v2 的 236.74 变为 274.52，
   退让 15.9%，退化全部来自 Bearing3_4（153.88 -> 271.22）。3_4 的总体 RMSE
   同期从 479.0 降到 301.5，是总体收益的主要来源，两者是同一取舍的两面。
2. 小样本轴承仍高估：Bearing2_4（42 条，真值均值 20.5 分钟）预测均值 242~317
   分钟（开发机 / 容器）。已缓解，未根治。
3. 公开验证集仅 3 根轴承，其中 90% 样本来自同一根，指标对分布变化敏感；所有
   选型都要求“邻域内多个取值同时成立”，但 5% 级改进仍在噪声边界内。
4. 成绩有 3%~4% 环境依赖：同一配置开发机 313.79、容器 302.75，各自可逐位复现。
   报告以容器值为提交口径，并给出 302~314 区间，不承诺精确到小数。
5. 这套方法没有“越训越好”的累积能力：权重平均点不可续训（302.75 起训 3 轮、lr 1e-4
   即退回 352.7，6 条轨迹从 381~705 收敛到 352~354）。镜像已加硬约束：检测到
   aggregate=weight_average 就不再从它续训，改从官方起点独立训练下一候选
   （0.5 版实测 305.99 / 342.01，均被门控回滚）。闭环本质是“多次独立尝试 + 选优”。
6. 集成把单轮训练成本放大 6 倍（3 秒 -> 45 秒）；若预算被压到 50 epoch 以内，
   只能退化为单轨迹，最好结果 434.68（仍优于官方基线 36%）。账面 epoch（255）
   是每条轨迹的轮数，真实训练量 1530，两者都在 summary 里分别记录。
7. 留一轴承 OOF 仍为 1,154（v2 口径，9 折未重跑），新工况上的优势会小于验证集数字。
8. 平台没有公开"从哪个路径取模型"的契约。本版同时写 /app/checkpoint.npz、
   best_checkpoint.npz，并在 summary 里给出 submitted_checkpoint 与 sha256，
   三条路径都指向同一份权重；但若平台另有约定路径，仍以平台契约为准。
